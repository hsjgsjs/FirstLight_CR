# 实力提升阶段：训练与输入改造计划

记录日期：2026-10-16。本文是从“像人”阶段转向“提升实力”阶段后的总体计划，汇总此前讨论的取舍与顺序。除标注“已有”和第 3.1 节“已实现”外，本文列出的输入、辅助任务和对手池调整均尚未实现。

阶段背景见[训练过程记录](sparring_journey_zh.md)第七节；循环赛结果见[固定条件循环赛](round_robin_zh.md)；在途动作与短期预测的数据通路、迁移与验收细节见[时序架构计划](temporal_reasoning_plan_zh.md)。

## 1. 出发点

- 第一阶段目标是“像人”：不再空等约 120 秒、法术不提前激活国王塔、连续出牌间隔、出牌执行延迟。用户确认这些目标已基本实现。
- 2026-10-15 至 10-16 的五模型正常开局循环赛（两份各 21 组，确定性出牌）合并后，Update 48、PPO 104、PPO 1208、BC 200 相对 General 460 均在约 ±25 Elo 内，没有测出明显更强的模型。最长一条路线约 1000 余次 PPO 更新（每次约 8 场），且早期优化目标并非实力，这个结果在预期之内。
- 实战录像中可见的典型问题：滚木已经出手、即将滚掉哥布林飞桶时，因哥布林落地又补牌；预判与拉扯不稳定。

## 2. 对各项提议的结论

| 方向 | 代码现状 | 结论 |
| --- | --- | --- |
| 在途动作显式输入 | 缺；只有预留圣水、占用手牌、上一拍动作与 LSTM 间接信息 | **做**，优先级最高 |
| 场上相对时空关系 | 已有类型化稀疏关系注意力（14 种关系）和成对空间偏置（dx、dy、距离、重叠）；实体有速度、部署剩余、投射物目标位置 | **只补时间维度**：接近速度、预计接触时间、是否在射程内、路线、到目标塔的预计到达时间 |
| 先选牌再选落点 | **已有**：gate → 候选（卡牌/技能）指针 → 以所选候选为条件的落点（FiLM），另有延迟与继续头 | 不做，重做动作头收益低、风险高 |
| 辅助预测 | 缺 | **做，但第一版只用一类低成本、无反事实污染的标签**（见第 4 节） |
| 记住对方关键牌 | **输入已有**：对方卡牌 token 带公开记牌可用性、`cycle_distance`、未知比例，及对方圣水上界与不确定度 | 不改输入；“不会利用”属于学习问题，“落点被预判”需要会读习惯的对手（见第 5 节） |

## 3. 第一项：一次迁移完成的新输入

合并为一次观测/模型版本升级，只付一次迁移成本（环境 → 训练精简观测 → 远程传输 → tensorizer → 模型 → 实战接管 → 检查点迁移 → 旧缓存“未知”掩码）。

**3.1 我方待执行动作集合**（固定上限的集合，不只是一个总剩余时间）

> **已实现（2026-10-16，“近期我方指令”）。** 由 tensorizer 记录策略自己每次决策提交的出牌/技能（最多 4 条），以自己的 `action_executed`/`action_rejected` 等事件判定执行或取消，执行后再保留 3 秒（60 tick）。每条输入：卡牌（可见/实际/形态）或技能、落点或技能来源、决策后已过时间、是否已执行、执行后已过时间。训练、评测、离线对战和实战接管走同一个 tensorizer，定义天然一致。模型把它汇总进循环核心和策略上下文，并把“待执行/刚执行”的落点画成两张空间图层供落点头使用。人类缓存旧分片按“未知”读入。观测/策略版本升为 `v4.1`；旧检查点加载时自动无损升级（见第 3 节末“迁移要求”）。费用未单独输入（卡牌身份已含）。因执行后仍保留 3 秒，滚木等**我方**已出手效果的“出手多久了、落在哪”也被覆盖，部分满足 3.2。

- 字段：卡牌/能力身份、动作类型、落点或能力来源、费用、状态、**提交后已经过的 tick**（除以训练延迟上限归一化）。
- 状态只保留训练与实战都能定义的两种：已提交但引擎未执行；已执行、效果仍在途。“点击已发出”“游戏已确认”只在实战存在，不作为模型输入，避免定义不一致。
- **不输入真实剩余时间。** 训练环境知道本次抽到的执行延迟，实战不知道；输入它等于给训练特权信息。输入两边都能精确计算的“已过时间”，由模型学习延迟分布。
- 区分“已知空集合”和“旧缓存无此记录”；人类录像样本没有决策时刻信息，统一标为未知，不标为空。

**3.2 已执行但效果在途**（尚未实现：实体级预计命中时间）

滚木重复防守主要属于这一段：命令已执行，滚木在场上滚动。给滚动投射物、飞行中的法术、部署中的兵补充可信的剩余时间/预计命中信息；只用当前可见信息与我方确定的调度计算，无可靠值时标为未知。现有 `expected_impact_tick` 仅用于实体保留优先级，尚未作为特征输入。

**3.3 成对时间特征**（尚未实现）

在现有成对空间偏置的通道上增加接近速度、预计接触时间、是否在射程内、同一路线等；新列零初始化，骨干网络不变。

**迁移要求**：新分支初始输出贡献为零，旧参数和优化器状态按名称/形状映射；迁移前后初始输出与循环状态需验证等价。详见[时序架构计划](temporal_reasoning_plan_zh.md)第 5 节。

3.1 的实现方式：新模块正常初始化，但它们通往原有激活的三条通路（循环核心输入的新增列、策略上下文的新跳连、空间编码器输入的新增两通道）初始为零。`load_actor_critic_checkpoint` 识别旧合同后，把旧权重放回原位、加宽张量补零、Adam 动量按参数名搬运（新参数无状态），因此旧检查点（General、Active IL、速猪、1208、BC 200）在评测、实战、固定对手和热启动中输出与之前完全一致，梯度仍能到达新参数。测试覆盖：输出逐元素一致（有/无/未知近期指令三种输入）、新通路有梯度、优化器动量对应、仓库内五个旧检查点逐张量核对。3.2/3.3 后续沿用同一升级方式。

## 4. 第二项：辅助预测“会不会被已存在的来源击杀”

**动机**：多补一张牌的代价只是 2–3 费，对胜负的影响被整局上千次决策的噪声淹没；少补一张而滚木没滚到，可能直接掉塔。只要模型对“已经能解掉”没有把握，“总补一张保险”就是 PPO 在这种不确定性下的合理收敛点，单靠胜负奖励很难纠正。需要让“这群单位已经会被解掉”成为表示中容易读出的信息。

**标签**：对每个敌方单位，预测它在未来 0.5/1/2 秒内是否被**决策时刻已存在**的我方来源击杀（场上滚木、飞行投射物、我方单位与塔）。

- 原生训练引擎中实体 ID 跨帧稳定，死亡事件带伤害来源，标签可从同一局后续观测生成。
- 被决策后新出的牌击杀，标签记为否，因此补牌不会污染标签，避开反事实问题。
- 只取 PPO 自己的对局，不改实战推理输入，不碰人类缓存。
- 实现前需抽查伤害来源归属在溅射、子单位、技能击杀等情形下是否可靠。

**控制风险**：预测头接在共享表示上，系数从小值开始（例如 0.05），只在 PPO 更新中加入；保留不加该损失的同源对照；以第 6 节的冗余防守率和循环赛判断效果，辅助损失下降本身不算实力提升。

“动作预计何时执行”不单独做辅助目标：在训练中只是在学延迟分布，3.1 的“已过时间”输入已覆盖。

## 5. 第三项：对手池

- 当前冻结对手只有 Active IL、General、hog26-specialist1，且确定性出牌，不会读学习者的习惯，容易学到针对它们的打法（例如依赖抢先出手）。
- 定期把训练中的检查点加入冻结对手池（联赛式），并考虑采样出牌的冻结对手；之后再评估专门针对当前模型的对手。
- “加农炮总放在同一位置被地震预判”这类问题，只有对手会利用时才会受到惩罚，改输入解决不了。

## 6. 评测与防退化

- 主评测：固定条件正常开局循环赛（`round_robin.sh`），多次运行必须合并后读结果，不看单次 21 组。
- 关键问题用定向对比：新模型对 General 460、新模型对迁移前同源模型，持续加组直至区间能排除设定差距（例如 ±3 个百分点，约需每对 1000 局量级）。
- 确定性与采样两种条件分开记录；采样条件使用用户提供的实战出牌温度 0.2，所有模型同一温度。
- 新增“冗余防守率”统计：我方出牌时，目标敌群已会被已存在来源击杀的比例。判定逻辑与第 4 节标签共用。
- 每 50–100 次更新与固定基准自动对比一轮，明显下降时回退；每阶段新目录、保留足够检查点、一次只改一个变量。

## 7. 实施顺序

1. 评测基础：合并现有循环赛结果（两份组号不重叠）；补冗余防守率统计；运行温度 0.2 的采样条件评测。
2. 新输入：3.1 已实现，按第 8 节与同源对照比较；3.2、3.3 待 3.1 的结果后再做。
3. 辅助预测头（第 4 节），带对照。
4. 对手池调整（第 5 节）。
5. 不做：动作头分层重做；对方记牌输入改造。

每一步的结论都以合并后、区间足够窄的固定条件评测为准，并按[训练过程记录](sparring_journey_zh.md)第 6.4 节要求记录。

## 8. 开始训练：近期指令的同源对照实验

目的：判断 3.1 新输入本身有没有用。两次运行除代码版本外完全相同：同一个起点、同一份参数（含 6–10 间隔、人类 BC 设置）、同样 200 次更新。新输入实验加载旧检查点时自动无损升级，起点输出与对照完全相同，差异只来自训练中学到的东西。

**第一步，对照（旧代码，现在就能跑）。** 在未拉取新代码的仓库中，按[人类 BC 操作说明](human_bc_zh.md)“连续出牌间隔与提前量”一节，从 BC 200 准备 `runs/human-trial-gap-v2` 并启动 `spar16-human-gap-v2`，200 次更新约 2 小时。

**运行期间不要拉取或合并新代码。** 续训、自动重试或远程 worker 会启动新的 Python 进程；新旧代码混用会让传输格式不一致而报错，对照也会在续训时被自动升级成带新输入的模型。

**第二步，新输入（对照结束后）。** 拉取新代码，用对照的同一份起点和参数启动：

```bash
CR_PPO_CHECKPOINT="$PWD/runs/human-trial-gap-v2/baseline.pt" \
CR_PPO_RESUME_CHECKPOINT="" \
CR_PPO_EXTRA_ARGS="$(cat runs/human-trial-gap-v2/human-options.txt)" \
CR_LAB_KEEP_CHECKPOINTS=100 \
bash native_runner/training/v4/lab_ppo.sh start spar16-recent-v1 200
```

启动日志里加载起点不报合同错误即为升级成功；保存的新检查点合同为 `v4.1`，旧代码无法加载，旧代码环境（例如尚未更新的实战机器）需先更新。

**第三步，评测。** 循环赛模型设为 General 460、BC 200、两次运行的最终检查点，采样、温度 0.2、间隔 6–10，各机器合并结果后比较“新输入对对照”这一对。同时实战录像观察滚木/法术已出手后的重复补牌是否减少。两者差距在区间内不显著时，不据此宣称有效，可延长两边训练再比。
