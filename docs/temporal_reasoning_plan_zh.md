# 通用时序表示与短期局面预测：设计记录

记录日期：2026-10-15。本文是实现前的设计与验证计划；在途动作的新输入、预计命中时间特征及短期预测辅助任务均尚未实现。现有模型、检查点和人类缓存不会因为本文更新而改变。

实战录制和出牌间隔的操作命令见[实战录制与训练操作](targeted_training_live_recording_zh.md)，已完成的人类 BC 短实验见[200 次更新结果](human_bc_trial_200_zh.md)。

## 1. 问题与证据边界

用户实测反馈包括：火球打到移动目标身后；加农炮等下得太晚或落点偏差导致拉扯失败；滚木已出手，在哥布林落地后又重复出兵；敌军可能被塔击杀却仍额外补防。另有提前滚木成功预判的实例，说明能力并非完全不存在，稳定性和不同交互的表现有差异。

这些现象共同指向短期局面演化、已提交动作效果和防守必要性的估计问题，但不能仅凭现象确认根因。额外出兵是否有反攻或保塔价值、实际投射物能否命中、塔是否会转移目标，仍需逐例核对。优先改进通用时序表示和验证方法，不先启用某张法术的专项采样。

已核对的代码事实：

| 项目 | 当前状态 | 代码入口 |
| --- | --- | --- |
| 单位速度、部署剩余时间、投射物位置/伤害/目标 | 已有相关特征；具体帧是否可信、是否保留仍需检查 | `training/v4/tensorizer.py` 的 `_groups` |
| 塔攻击冷却、攻击阶段、目标关系 | 已有特征和关系边 | 同文件 `_towers`、`_relations` |
| 上一拍动作与历史 | 上一拍动作编码及 LSTM；不是持续的完整待执行队列 | 同文件 `record_action`；`model.py` |
| 待执行命令 | 环境内部跟踪并预留圣水/手牌；训练的 `policy_features_only=True` 观测省略 `pending_actions`，模型没有对应独立输入集合 | `battle_env.py` 的 `_pending_for`、`observe`；`tensors.py` |
| `expected_impact_tick` | 在 tensorizer 中用于实体保留优先级，没有作为明确的剩余命中时间特征 | `tensorizer.py` 的 `_child_priority` |
| 短期未来预测 | 当前没有独立的位置/存活/血量演化辅助头及监督流程 | `model.py`、`ppo.py`、`learning.py` |

上表代码路径除另行标注外均相对 `native_runner/`。待执行动作缺少独立输入，不等于策略完全看不到自己出牌：动作掩码、预留圣水、事件、上一拍动作和循环记忆仍提供间接信息。

## 2. 时间边界：先测量，不能先认定实战更慢

训练参数 `--execution-delay-ticks 18-24` 表示从决策观测 tick 到引擎执行出牌，随机 0.9–1.2 游戏秒。之后的兵种部署、投射物飞行和法术效果由同一个游戏引擎继续计算。该参数不是到“兵开始走动”，也不会再额外叠加一次客户端约 21 tick 的命令延迟。

实战经历观测采集、推理、可能的连续操作间隔等待、ADB 点手牌/落点、客户端执行，以及兵种部署或法术效果。官方约一秒的操作延迟与训练范围接近，尚无实测证明延迟差是主要原因。

实战程序的 `LAND_TICKS=26` 是带余量的回执估计，不是实测，也不是一次额外强制等待 1.3 秒。录制里的 `execute_tick_estimate` 不能当作生效证据。

需要分别核对：

1. 决策观测 tick 到真实 native `card_play`：包含观测后的策略/输入路径耗时。
2. 点击完成到真实 `card_play`：与客户端操作延迟比较，考虑点击与事件匹配是否唯一。
3. `card_play` 到单位/投射物 `spawn`：与兵种和法术过程有关。
4. 单位开始活动或法术命中：属于后续游戏过程，不能直接用 `spawn` 时间替代。

现有录制保存这些分析所需的原始观测和点击事件，并在能唯一关联时记录决策到 `spawn` 的时间；完整分阶段统计、开始活动和命中关联尚未实现。需要使用一致的时间边界比较训练与实战，不能把部署/飞行总时间再填进执行延迟而重复计算。

连续动作最小间隔独立于执行延迟：旧训练保存参数可能是 `4-8` tick，新默认 `8-12` tick，即 0.4–0.6 秒。改变这个参数应作为单独实验记录。

## 3. 第一阶段：补齐通用时序输入

这是中等规模的数据通路和模型输入升级，不需要重建整个策略。优先保留现有语义编码器、空间编码、LSTM、策略头和价值头。

### 3.1 尚未执行的动作

增加有上限的我方待执行集合，候选字段包括：动作/卡牌身份、动作类型、落点或能力来源、提交后经过时间、预计剩余时间、排队/取消/拒绝状态及时间来源是否可信。预计时间应体现执行延迟和连续动作间隔调度后的结果，不使用模型被忽略的原始延迟标签冒充实际调度。

贯通环境内部队列、训练精简观测、resident/remote 传输、tensorizer、模型编码和实战接管。每局重置与动作取消要正确清除状态；到预估执行时间后不能在没有证据时直接断言成功。

只提供策略自己已提交的命令及依法可见的结果，不暴露敌方私有待执行命令。新特征区分“已知空队列”与“旧缓存中没有这份记录”。

### 3.2 已执行但效果仍在途中

排队命令结束，不等于其效果已完成。滚木、飞行中的火球、正在部署的兵，需要在可见实体/效果表示中持续存在，并关联可信的来源、运动、范围、目标与剩余时间。重复防守的滚木实例主要涉及这一阶段，仅加入待执行命令队列不够。

在已有实体特征上补充时间信息，或增加小的时序分支。预计命中/部署时间只在当前可见信息或明确可信的我方调度支持时使用；没有可靠值时标为未知，不填成“立即命中”，也不把引擎隐藏的未来时间表作为 FAIR 输入。预计命中不等于保证命中，转向、目标消失和路径变化都可能使其失效。

## 4. 第二阶段：短期预测辅助任务

这部分工作量较大，主要难在实体对应、标签语义、动作条件和验证，预测头本身可以很小。第一版可在现有共享表示上增加 0.5/1/2 秒的位置、存活和血量变化预测；暂不把它扩展为完整世界模型或长程规划系统。

监督来自实际后续观测，未来只作为训练标签，不输入当前策略。需要处理：跨帧实体身份、生成/死亡、隐身或移出可见范围、观测时间不均匀、对局结束、缺失帧和事件环不完整。看不见不能直接标为死亡；跨 episode/generation 的样本不得配对。需要考虑预测期间实际执行的动作，以及敌方尚不可知的行动导致的结果不确定性。

“未来预测准确”也不等于已经解决反事实决策：如果滚木后又补了骑士，哥布林未碰塔，不能据此标注“没有骑士也不会碰塔”。判断补防必要性，应使用没有新增干预的片段或经过验证的受控复现；即使不补防，对手仍可能在期间行动，也要保留这个条件。

辅助损失先小规模试验，检查与 PPO 的梯度相互影响。辅助标签若单独使用特权未来事实，必须明确训练边界、缺失掩码和评测目的，绝不能泄漏进推理输入。预测结果无需作为“禁止出牌”的硬规则。

## 5. 检查点、优化器和缓存迁移

当前检查点严格验证模型/数据契约并严格加载权重，不能新增输入后直接忽略不匹配继续 `resume`。

拟采用专用迁移入口：原参数复制到新模型，新时序分支从输出贡献为零的状态开始；如扩展既有线性输入，复制旧列、将新列初始贡献置零。需要按实际接入方式验证等价性，不能认为“新增 token 值为零”就不会改变注意力归一化。新分支仍须具备可训练的梯度通路。

原优化器状态按参数名称和形状映射；扩展张量的旧部分保留 Adam 状态，新部分初始化，新参数没有旧状态。优化器参数组、温度和剩余退火进度单独迁移并记录，不能直接套用旧参数序号。保留原检查点与迁移清单，使用新的实验目录和版本契约。无须从零训练，但不能保证迁移后训练不会退化。

现有 1 万场人类缓存保留：新增字段缺失时用“未知”掩码接入，能从可信旧数据恢复的部分单独审计，无法恢复的精确队列时序不编造。现有缓存缺少显式未来标签或实体标识时，是否需要重新重建取决于字段覆盖；不能预先承诺全部无需重建。实战录制原始档案同样保留全部输赢与错误，训练使用标记另存。

## 6. 实施顺序与验收

1. 固定当前基准与人类 BC 200 检查点，收集并核对滚木重复防守、塔能自行解场、下兵拉扯的实例；记录真实延迟、落点映射和输入是否缺失。
2. 实现我方待执行动作表示，以及已有在途效果的可信时间特征；贯通训练和实战，完成版本/检查点/缓存迁移。
3. 做只有新输入的短实验；与同源基准在一致卡组、种子、双方位置、温度和操作时序下比较。
4. 信息通路验证后，再单独试短期预测辅助任务，并保留不加该损失的对照。

验收至少包括：队列跨多个 WAIT 持续、连续调度、取消/拒绝与每局重置；未知/已知空状态区分；可见性边界；时间单位和时钟一致；迁移前后初始输出及循环状态等价；缓存读取及训练/实战输入一致；跨段标签不串局；额外 CPU/GPU 内存与吞吐开销。

策略效果同时观察重复解场、漏防、塔受到的伤害、拉扯成功和正常完整对战表现。辅助预测损失下降、出牌变少或某类局面耗水减少，均不能单独证明实力提升。当前不存在这套专用基准的自动统计或自动选优/回滚，实施时需补齐所需测量。
